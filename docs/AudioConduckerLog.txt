#2
PipeWire: impl_ext_end_proxy called from wrong context

in test_main.cpp, pw_main_loop_run in a standalone thread. This means every event callback like NodeObserver::registry_event_global is executing in this thread. But some functions will call low-level Proxy operation like PipeWireBackend::setVolume, this will use pw_node_set_param, which is not thread-safe, may lead to error context or undefined behavior.

To solve this thread (or context) problem, we shouldn't call these APIs like pw_proxy_destroy, pw_node_set_param directly. We should encapsulate them as events, and then send them to PipeWire's main loop to execute. So we use pw_loop_invoke to achieve safe cross-thread usage.
